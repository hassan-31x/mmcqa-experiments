# mmcqa-experiments

Phase 1 (QLoRA fine-tuning of Qwen3.5-4B) and Phase 2 (CulturalPangea + Qwen ensembles) for SemEval 2027 Task 6 (MMCultureQA), Task 2. The reasoning, decision rules and design live in [`../plans/`](../plans/README.md). This file is the operating manual.

**One Kaggle account: run the notebooks one after the other.** Kaggle only generates answers; scoring and analysis happen on the Mac.

## Layout

| Path | What |
| --- | --- |
| `mmcqa_exp/` | Kaggle-side package: `settings` (all pins), `data`, `prompts`, `postprocess`, `jobs`/`worker`/`launcher`/`merge` (generation pipeline), `backends/` (qwen, pangea, fake), `sft/` (QLoRA training), `phase1.py`, `phase2.py`, `env_setup.py` (Pangea venv) |
| `kaggle/phase1`, `kaggle/phase2` | notebook + `kernel-metadata.json` per phase (generated by `scripts/make_notebooks.py`) |
| `local_analysis/` | Mac-side: `pull.sh`, `score`, `retrieval`, `mbr`, `ensemble_select`, `judge`, `compare`, `import_old_run` |
| `tests/` | CPU tests (see below) |

## Run order

### 0. Local tests (about 2 minutes)
Needs an environment with torch, transformers>=5, peft, torchvision, scikit-learn, pandas, matplotlib, pillow (the first run downloads a few MB of Qwen processor files):
```bash
python -m unittest discover -s tests -t .
```

### 1. Push (ask first: this publishes code)
Create `hassan-31x/mmcqa-experiments` on GitHub (**public**, because the notebooks clone it without a token; or upload the folder as a Kaggle Dataset and attach it, the clone cell then copies it from `/kaggle/input`), then `git add . && git commit && git push`.

### 2. Smoke runs (each about 40 min of GPU)
```bash
../.venv-local/bin/kaggle kernels push -p kaggle/phase1     # notebook starts with LIMIT = 4
```
(or paste the notebook into a Kaggle notebook: GPU **T4 x2**, Internet on, Save & Run All.) Check the notebook output:
- Phase 1: two trainers finished; `sft_*_sizing.json` shows **sec/step**; peak memory <= ~14.5 GB; sft answers are non-empty and in the right script. Multiply sec/step by 2,500 steps: if `TRAIN_HOURS = 6` covers less than ~30% of an epoch (< ~750 steps), tell the user before the full run (options: `QWEN_MAX_PIXELS` 384², batch 2x8, accept a partial epoch).
- Phase 2: Pangea worker logs show transformers 4.37.x, Qwen workers 5.16.x; all stages 16/16; note Pangea's `peak_mem_gb` (< 7 GB -> set `PANGEA_WORKERS = 2`).
- Pull and score the smoke outputs locally (section 4) to prove the loop closes.

### 3. Full runs
Set `LIMIT = None` and run Phase 1, then Phase 2 (Save Version -> Save & Run All (Commit)). Pull each with:
```bash
local_analysis/pull.sh muhammadhassan31/mmcqa-phase1-finetune phase1 2026-11-05_full
local_analysis/pull.sh muhammadhassan31/mmcqa-phase2-ensemble  phase2 2026-11-05_full
```

### 4. Local analysis (scorer env = `../../external/.venv-scorer/bin/python`, analysis env = `../.venv-local/bin/python`)
```bash
A=results/analysis/r1; P1=results/phase1/TAG; P2=results/phase2/TAG; SC=../../external/.venv-scorer/bin/python; PY=../.venv-local/bin/python
$PY -m local_analysis.retrieval --out $A                                         # tfidf_retrieval candidate
$SC -m local_analysis.score --runs $P1 $P2 --out $A                              # official scorer, per-item scores (incremental)
$SC -m local_analysis.mbr --runs $P1 $P2 --out $A --pool pangea_p0 qwen_z1 sft_S1 tfidf_retrieval cascade_qwen2pangea fusion_qwen   # add sft_S2 / qwen_z1_s0 / qwen_z1_s1 if present; ~30-60 min CPU
$PY -m local_analysis.ensemble_select --runs $P1 $P2 --out $A                    # pools are built from what exists
$PY -m local_analysis.judge --out $A --systems pangea_p0 qwen_z1 sft_S1 sft_S2 cascade_qwen2pangea fusion_qwen --history-systems culturalpangea_7b qwen3_5_4b --dry-run
#   show the user the count and estimated cost, get approval, then rerun without --dry-run (about $2)
$PY -m local_analysis.compare --analysis $A --phase1 $P1 --phase2 $P2 --run-tag r1   # -> results/report/phase_report.md
```
The pipeline was verified on the old dev100 runs: scoring reproduces the published numbers (e.g. Pangea 0.737/0.685/0.711 on MSA/Egyptian/Levantine).

## Operational notes
- Every stage is resumable: re-running the same notebook cell skips answered items. Errored items are retried (2 rounds) and fall back to the question text, never an empty answer.
- `--stages fusion_qwen` reruns one Phase 2 stage from merged files on disk. `--samples` adds two sampled Qwen candidates for MBR.
- Kernel speedups are not enabled: Qwen3.5's linear-attention layers run on a slower PyTorch path on T4 (`flash-linear-attention` is not installed). The smoke run's sec/step tells you how much that costs. Do not try compiling kernels mid-project.
- Kaggle's `machine_shape: "NvidiaTeslaT4"` is reported to give T4 x2; the notebooks print `nvidia-smi -L`. Both orchestrators also work with a single GPU (Phase 1 then trains S1 only).
- Never tune on devtest. The optional `--devtest` flags are for producing submission files with a model already chosen on dev.
